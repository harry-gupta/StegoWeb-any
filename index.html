    How StegoWeb works

    Steganography hides data inside another medium. StegoWeb uses LSB (Least Significant Bit) substitution: the last bit of every RGB channel carries one bit of your secret. That changes each channel by ±1 out of 255 — invisible to the eye.

    Encoding pipeline

    1. Your cover image is decoded into raw RGBA pixels on a canvas.
    2. Your secret is packaged: text is UTF-8 encoded; files are stored with filename + raw bytes.
    3. If you supply a password, the entire payload is encrypted as one unit with AES-256-GCM.
    4. The ciphertext is split into N chunks if it exceeds the per-image capacity.
    5. Each chunk gets a header with index, total count, original size, and filename.
    6. Each chunk is embedded in its own upscaled copy of the cover, exported as a lossless PNG.
    7. Multi-chunk output is packed into one ZIP (with a manifest) for a single download.

    Decoding & validation

    The decoder reads the embedded index from each PNG, never the filename. On decode it:

    • Silently drops duplicate chunks (same embedded index).
    • Aborts with an alert if any chunk is missing — no partial decode is attempted.
    • Sorts by index and concatenates.
    • Decrypts (if applicable) and verifies the final size.
    ⚠️ All chunks must be present to decode. AES-256-GCM authenticates the entire stream at once, so a missing chunk makes decryption mathematically impossible.

    Privacy

    Zero uploads. No backend. No analytics. All cryptography uses the browser's native Web Crypto API.
